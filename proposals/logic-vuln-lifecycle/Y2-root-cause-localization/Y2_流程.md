# Y2 流程

```
【輸入】Y1：有漏洞的網址 ＋ 攻擊請求 ＋ 執行紀錄
   │
   ▼
① 找路
   1-1 在測試環境啟動目標網站，掛上方法呼叫記錄與資料庫查詢記錄
   1-2 重送攻擊請求
   1-3 記錄方法呼叫序列與實際執行的資料庫查詢
   └→ 產出：攻擊路徑（入口 → 業務邏輯 → 資料存取 → 資料庫查詢）
   │
   ▼
② 找缺
   2-1 依 Y1 的攻擊寫出被違反的規則（資源／動作／必須滿足的條件）
   2-2 列出攻擊路徑上的檢查（框架權限設定／if 判斷／查詢條件）
        ├ 有鄰居 → 參考鄰居共同呼叫的方法，辨識專案自訂的檢查
        └ 無鄰居 → 只認框架權限設定、if 判斷、查詢條件
   2-3 比對：規則要求的條件，路徑上是否有執行
   └→ 產出：被違反的規則 ＋ 路徑上未執行該條件的位置 ＋ 證據
   │
   ▼
③ 找範圍
   3-1 從攻擊路徑的資料庫存取點，沿呼叫圖往回找出所有入口網址
   3-2 每個入口重做 2-2 ～ 2-3
   3-3 決定補在哪一層：
        ├ 有鄰居 → 依鄰居的檢查多寫在哪一層
        └ 無鄰居 → 預設規則
   3-4 排出修補優先順序（是否為 Y1 實際打穿的入口／操作種類／可觸及者／資料敏感度）
   └→ 產出：受影響入口清單 ＋ 建議補的位置 ＋ 替代位置 ＋ 修補優先順序
   │
   ▼
④ 驗證
   4-1 在建議位置於執行時臨時插入檢查
   4-2 重送攻擊請求
   4-3 重送正常使用者請求
   4-4 判讀：
        攻擊被擋 且 正常通過 → 驗證成功，進入【輸出】
        攻擊仍成功           → 回 ②，換下一個嫌疑
        正常被擋             → 調整檢查條件，回 4-1
   │
   ▼
【輸出】交給 Y3：錯在哪、缺什麼檢查、建議補的位置與替代位置、修補優先順序、驗證結果
```
